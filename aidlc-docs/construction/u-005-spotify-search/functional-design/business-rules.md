# U-005 비즈니스 규칙 (Business Rules)

<!-- markdownlint-disable MD013 -->

본 문서는 U-005 Spotify Search API 연동 및 트랙 매핑 과정에서 적용되는 규칙과 예외 대응 정책을 정의합니다.

## 1. 텍스트 트랙 검색 쿼리 빌딩 규칙 (Question 2 - Option B)

- **검색 정확도 최우선 필터**: AI가 추천한 텍스트 기반 곡 정보(`CuratedTrack`)로부터 실제 음원을 매핑할 때, 검색 결과 오염을 방지하기 위해 엄격한 구조화 쿼리를 적용합니다.
  - 검색 쿼리 형식: `"track:\"${title}\" artist:\"${artistName}\""`
  - 정확한 따옴표 래핑을 통하여 곡 제목과 아티스트명이 완전히 일치하는 검색 결과만 Spotify Web API로부터 요청하도록 강제합니다.
- **대체 검색 미수행**: 구조화 필터에 의해 검색 결과가 나오지 않을 경우, 유사 텍스트 키워드 기반의 범용 단순 텍스트 조합(`"{title} {artist}"`) 2차 재검색은 의도적으로 시도하지 않고 검색 실패로 결론짓습니다. (구현 단순성 및 정확도 최우선 정책)

## 2. 검색 매칭 실패 시 후보 제외 규칙 (Question 1 - Option A)

- **누락 트랙 과감한 스킵**: 특정 곡이 Spotify 데이터베이스에 존재하지 않거나 위의 정확도 필터에 의해 검색 결과(`tracks.items`)가 반환되지 않는 경우, 해당 곡을 플레이리스트 구성 요소에서 **제외(Exclude)**합니다.
- **볼륨 대체 미수행**: 매칭에 실패하여 추천 볼륨(곡 개수)이 줄어들더라도, 사용자의 최근 재생 곡이나 임의의 대체 곡으로 강제 보정하지 않고 성공적으로 매칭된 곡들로만 이루어진 플레이리스트(`SearchCurationResult`)를 반환합니다.

## 3. 개별 검색 오류 격리 및 내결함성 규칙

- **개별 예외 복원**: 추천된 N개의 곡 중 특정 곡 검색 중 발생한 HTTP 네트워크 장애, 개별 호출 타임아웃 등의 예외 사항은 전체 플레이리스트 생성 프로세스를 중단시키지 않습니다.
- **에러 격리**: 개별 검색 실패는 단순 매칭 결과 없음(스킵)과 동일하게 취급되어 최종 플레이리스트에서만 누락되며, 상위 호출 흐름에는 어떠한 예외도 전파하지 않습니다.
- **최종 최소 요건**: 다만, AI가 추천한 전체 트랙 목록 중 매칭에 성공한 곡이 1건도 없거나 심각한 Spotify API 전면 마비 등의 사유로 매칭 트랙 수가 0개인 경우에만 플레이리스트 생성 불가 에러를 발생시킵니다.
