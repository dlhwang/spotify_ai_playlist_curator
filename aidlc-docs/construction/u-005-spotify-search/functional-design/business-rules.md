# U-005 비즈니스 규칙 (Business Rules)

<!-- markdownlint-disable MD013 -->

본 문서는 U-005 Spotify Search API 연동 및 트랙 매핑 과정에서 적용되는 규칙과 예외 대응 정책을 정의합니다.

## 1. RAG 다중 쿼리 라운드 검색 규칙

- **다중 라운드 병렬 검색**: 검색 결과의 다양성 확보와 2~3시간 플레이리스트(최종 30~50곡) 구성을 위해, 한 번의 검색 대신 쿼리 계획(`SearchQueryRound[]`)에 정의된 여러 쿼리 및 오프셋을 기반으로 Spotify Search API(`GET /v1/search`)를 다중 병렬 호출합니다.
- **페이지 오프셋 확장**: 단일 쿼리당 `limit`는 최대 10건으로 제한하되, `offsets` 배열(예: `[0, 10]`)을 통해 다중 페이지를 검색하여 80~150곡의 넓은 1차 후보군을 확보합니다.
- **아티스트 깊이 확장 검색**: 커버리지 검증에서 도출된 타겟 아티스트별 깊이 요구사항(`artistDepthTargets`)에 따라, 해당 아티스트의 곡을 추가로 획득하기 위해 `artist:"{artistName}"` 쿼리로 아티스트 중심 추가 검색을 강제합니다.

## 2. 개별 트랙 3단계 정밀 매핑 규칙

- RAG 후보군 선별 실패 시 또는 개별 트랙 매핑 시, 곡 매칭 성공률을 극대화하기 위해 다음 3단계 검색 필터를 순차적으로 적용합니다.
  - **1단계 (엄격한 구조화 필터)**: `track:"{cleanTitle}" artist:"{cleanArtist}"` 쿼리로 정확한 음원을 1차 검색합니다.
  - **2단계 (괄호 및 부가정보 정제 필터)**: 1단계 실패 시, 곡명이나 아티스트명에 포함된 괄호 내용(예: `(Radio Edit)`, `[2026 Remaster]`)을 정규식으로 제거한 후 `track:"{strippedTitle}" artist:"{strippedArtist}"`로 2차 검색을 수행합니다.
  - **3단계 (느슨한 키워드 필터)**: 2단계마저 실패 시, 필터 키워드 없이 공백으로 조합된 `{cleanTitle} {cleanArtist}` 쿼리를 날려 검색 성공률을 마지막으로 확보합니다.

## 3. 검색 실패 시 복원력 및 폴백 규칙

- **개별 오류 격리**: 특정 쿼리나 오프셋 조회 시 발생하는 HTTP 네트워크 오류, 5초 타임아웃(`AbortError`) 예외는 전체 프로세스를 중단하지 않고 로그 기록 후 해당 트랙/쿼리만 과감히 스킵(Exclude) 처리합니다.
- **전면 실패 시 최근 재생 곡 폴백**: 스포티파이 API 전면 마비, 네트워크 다운, 혹은 최종 검색된 후보 트랙 수가 0개인 경우 에러를 던지지 않고, 사용자의 최근 재생 곡 목록(`recentTracks`) 중 최대 30곡을 플레이리스트 트랙으로 이식하는 폴백 결과(`createFallbackResult`)를 반환하여 무중단 큐레이션을 보장합니다.

## 4. 토큰 만료(401 Unauthorized) 자동 재시도 규칙

- **세션 자동 갱신**: Spotify Search API 호출 중 `401 Unauthorized` 상태 코드가 반환되면 세션 만료로 간주합니다.
- **1회 자동 재시도**: 백엔드는 즉시 세션 내 `refreshToken`을 이용해 Spotify Access Token을 갱신(`authService.refreshSession`)하여 쿠키 스토어에 재기록하고, 실패했던 검색 요청을 1회에 한해 새로운 토큰으로 자동 재시도합니다. 갱신마저 실패할 경우에만 세션을 완전히 소멸시키고 에러를 전파합니다.
