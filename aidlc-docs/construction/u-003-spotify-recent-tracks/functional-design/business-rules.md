# U-003 비즈니스 규칙 (Business Rules)

<!-- markdownlint-disable MD013 -->

본 문서는 Spotify 최근 재생 곡 수집 및 연동 과정에서 적용되는 규칙과 데이터 처리 방식을 정의합니다.

## 1. 도메인 정제 및 필드 추출 규칙 (Question 1 - Option C)

- **최소 정보 모델링**: MVP 수준의 효율성과 큐레이션 속도를 극대화하기 위해 Spotify API 원본 응답에서 플레이리스트 큐레이션 및 생성에 직접 관여하는 핵심 정보만 남기고 정제합니다.
- **필수 추출 데이터**:
  - `id`: Spotify 고유 트랙 식별자 (중복 확인용)
  - `uri`: 플레이리스트에 곡을 추가하기 위한 Spotify Resource 식별자 (예: `spotify:track:xxxx`)
  - `title`: 트랙 제목 (LLM 컨텍스트 전달용)
  - `artistName`: 주요 아티스트 이름 (LLM 컨텍스트 전달용)
- **제외 데이터**: 음원 상세 특성(Tempo, Energy 등), 상세 앨범 정보, 정확한 재생 시간(duration_ms) 등은 MVP 도메인 데이터 범위에서 배제합니다.

## 2. 빈 최근 재생 목록 처리 규칙 (Question 2 - Option C)

- **무중단 비즈니스 흐름**: 최근 재생 곡이 아예 없는 신규 계정이거나, 오랫동안 곡을 재생하지 않아 Spotify가 빈 목록(`[]`)을 반환하더라도 애플리케이션은 정상 동작해야 합니다.
- **데이터 전달 룰**:
  - `Track[]` 배열을 빈 상태(`[]`)로 유지한 채 다음 큐레이션 레이어(LLM 입력부)로 그대로 전달합니다.
- **큐레이션 프롬프트 연동 룰**:
  - LLM 입력 조립기(Prompt Builder)는 최근 재생 트랙 목록이 비어있음을 감지하면, 최근 재생 스타일을 프롬프트에 융합하는 템플릿 영역을 생략하거나 기본 플레이리스트 생성 지시문으로 자동 전환하여 큐레이션을 지속합니다.

## 3. 예외 처리 및 관측성 규칙 (Question 3 - Option A)

- **인증 갱신 시도**: Spotify API 호출 시 `401 Unauthorized` 오류가 검출되면, 백엔드는 세션에 저장된 Refresh Token으로 1회 자동 갱신을 수행하고 기존 요청을 재시도합니다.
- **일시적/영구적 장애 제어 (403, 429, 5xx 에러)**:
  - 갱신 후에도 발생하는 인증 오류나 일시적 장애(500, 503), Rate Limit(429) 등의 심각한 외부 장애 시에는 API 흐름을 즉시 중단합니다.
  - **클라이언트 리다이렉션**: 사용자 화면에는 구체적인 외부 백엔드 스택을 노출하지 않고, `error=spotify_api_error` 와 같은 대표 오류 코드만 URL 쿼리에 실어 홈(`/`)으로 리다이렉트하거나 홈 UI에서 오류 토스트 메시지를 전시하도록 제한합니다.
  - **서버 측 관측성(Observability)**: 서버 로그에는 Spotify API 에러 코드, 상태 코드, 원시 응답 바디를 상세 스택로그와 함께 분석용 카테고리로 남겨 에러 모니터링이 가능하도록 규정합니다.

## 4. 데이터 정제 및 중복 제거 규칙

- **최근 순 정렬 보존**: Spotify API가 반환하는 순서(가장 최근에 재생된 순서)를 그대로 보존하되, 중복 재생된 곡은 제거합니다.
- **Unique Track 필터**: 동일 트랙 ID(`id`)를 가진 데이터가 리스트에 여러 개 존재할 경우, 재생 시점(`played_at`)이 가장 최근인 1건만 최종 `Track[]` 배열에 남기고 나머지는 필터링하여 데이터 구조를 경량화합니다.
