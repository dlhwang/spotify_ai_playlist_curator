# 성능 테스트 안내서 (Performance Test Instructions)

<!-- markdownlint-disable MD013 -->

본 문서는 애플리케이션의 성능 검증 상태와 향후 확장 방안을 기술합니다.

## 성능 검증 개요

본 프로젝트는 프로토타입 성격의 MVP(최소 기능 제품) 단계로, DB 없이 메모리와 API 우회 호출로 동작하므로 이번 CONSTRUCTION 단계의 필수 자동화 대상 성능 테스트 요구사항은 없습니다.

- **성능 검증 방식**: 로컬 개발 서버 작동 확인 및 단위 테스트 타임아웃(AbortController 기반 5초/10초 등) 모의 예외 발생 제어 검증으로 대체합니다.
- **상태**: 자동화 성능 테스트 스위트는 N/A(해당 없음) 처리되었습니다.

## 향후 확장 성능 테스트 계획 (권장)

추후 프로덕션 서비스 출시 단계에서 부하 테스트가 필요할 경우 다음 가이드를 준수합니다.

### k6 기반 Load Test

- **도구**: [k6](https://k6.io/) 오픈소스 부하 테스트 프레임워크 권장
- **시나리오**:
  1. 가상 유저(VU) 50~100명이 동시에 `POST /api/curate`를 호출하는 상황 모사.
  2. 외부 LLM API 및 Spotify API 호출 지연 시, 전체 Route Handler의 최대 동시성 수용 한계점 파악.
- **목표 성능 기준**:
  - 평균 응답 시간: 외부 API 응답 대기를 제외한 순수 백엔드 오버헤드 < 200ms
  - 429 Too Many Requests 발생 시 오류 전파 통제 성공률: 99.9% 이상
