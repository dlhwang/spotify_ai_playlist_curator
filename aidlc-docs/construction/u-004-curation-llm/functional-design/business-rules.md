# U-004 비즈니스 규칙 (Business Rules)

<!-- markdownlint-disable MD013 -->

본 문서는 U-004 Curation Engine 및 LLM 연동 과정에서 적용되는 규칙과 예외 대응 정책을 정의합니다.

## 1. 하이브리드 LLM 구동 규칙 (Question 1 - Option A)

- **API 활성 모드**: 서버 내 `LLM_API_KEY` 환경 변수가 올바르게 기입되어 있는 경우, 외부 LLM API(Gemini 또는 OpenAI 등)를 실시간 호출하여 큐레이션을 수행합니다.
- **모의(Mock) 서비스 모드**: `LLM_API_KEY`가 부재하거나 로컬 테스트 환경인 경우, 원격 장애를 막기 위해 **로컬 모의 엔진**이 자동으로 작동합니다.
  - 사용자의 프롬프트 텍스트를 분석하여, 분위기에 걸맞은 모의 플레이리스트 메타데이터(예: 프롬프트 키워드를 활용한 제목/설명 구성)와 임의의 모의 추천 곡 리스트를 생성하여 실시간 API 호출과 동일한 JSON 구조로 응답합니다.

## 2. 텍스트 기반 곡 추천 및 후속 검색 위임 규칙 (Question 2 - Option A)

- **LLM 데이터 스키마 제약**: LLM에게 최근 재생 곡 목록의 특정 URI에 한정하여 곡을 고르도록 제약하지 않고, 광범위한 음악 지식을 기반으로 자연어 분위기에 가장 적절한 곡들을 추천하도록 문을 열어둡니다.
- **결과 출력 사양**: LLM은 추천된 각 트랙의 **곡 제목(title)**과 **아티스트명(artistName)**의 텍스트 리스트를 반환합니다.
- **URI 획득 위임**: 해당 트랙들의 실제 Spotify URI 획득 및 검증 책임은 이 단위에서 처리하지 않고, 후속 단위(U-005)의 Spotify Search API 연동 컴포넌트로 완전히 위임합니다.

## 3. 파싱 에러 발생 시의 자동 복구 및 폴백 규칙 (Question 3 - Option A)

- **1차 자동 재수행**: LLM의 응답 내용이 정의된 JSON 규격을 충족하지 못해 파싱 오류(`JSON.parse` 예외 등)가 발생하는 경우, 백엔드는 즉시 파싱 실패 원인을 템플릿에 추가하여 1회에 한해 LLM에 수정 재요청을 보냅니다.
- **최종 폴백(Fallback) 수립**: 2차 재수행마저 실패하거나, LLM 호출 중 물리적인 네트워크 타임아웃/장애가 발생하는 경우에는 프로세스를 차단하지 않고 안전하게 준비된 디폴트 플레이리스트 데이터를 반환합니다.
  - **디폴트 폴백 결과 구조**:
    - 플레이리스트 제목: `"AI Curated Playlist"`
    - 플레이리스트 설명: `"AI 큐레이션 처리에 일시적인 오류가 발생하여, 사용자의 최근 재생 곡 목록을 기반으로 임시 구성된 플레이리스트입니다."`
    - 추천 트랙 목록: 사용자가 전달한 최근 재생 트랙 목록(`recentTracks`)의 텍스트(제목, 아티스트명) 중 최대 10건을 그대로 추천 곡으로 이식합니다.

## 4. LLM JSON 출력 유도 프롬프트 지시 규칙

- **System Instruction**: LLM이 반환하는 결과물은 마크다운 코드 블록이나 불필요한 설명 텍스트 없이 오직 순수한 JSON 문자열이어야 함을 시스템 지시어로 강제합니다.
- **Response Format 제약**: 지원하는 경우 API 호출 시 응답 포맷 옵션을 `{ type: "json_object" }`로 설정하여 파싱 안정성을 향상시킵니다.
