# U-004 비즈니스 규칙 (Business Rules)

<!-- markdownlint-disable MD013 -->

본 문서는 U-004 Curation Engine 및 LLM 연동 과정에서 적용되는 규칙과 예외 대응 정책을 정의합니다.

## 1. 하이브리드 LLM 구동 규칙

- **API 활성 모드**: 서버 내 `LLM_API_KEY` 환경 변수가 올바르게 기입되어 있고 `MOCK_LLM`이 `true`가 아닌 경우, 외부 LLM API(Gemini 또는 OpenAI 호환 API)를 실시간 호출하여 큐레이션을 수행합니다.
- **모의(Mock) 서비스 모드**: `LLM_API_KEY`가 부재하거나 `MOCK_LLM=true`인 로컬 테스트 환경인 경우, 원격 장애를 막기 위해 **로컬 모의 엔진**이 자동으로 작동합니다.
  - 사용자의 프롬프트 텍스트의 성격(Chill 여부 등)을 분석하여, 분위기에 걸맞은 모의 CurationSpecs, SearchQueryRound 계획, 모의 플레이리스트 메타데이터 및 추천 곡 리스트를 생성하여 실시간 API 호출과 동일한 JSON 구조로 응답합니다.

## 2. RAG 기반 큐레이션 및 의도 분해 규칙

- **3축 SPEC 분해**: 사용자의 자연어 프롬프트를 수신하면, LLM은 검색 쿼리를 도출하기에 앞서 의도를 3가지 SPEC(장르/감성 SPEC, 장소/청취 맥락 SPEC, 아티스트/곡 SPEC)으로 분해하여 구조화합니다.
- **후보군 기반 선별 (RAG)**: Spotify Recommendations API의 지원 중단(Deprecated)에 대응하여, LLM은 자체 지식으로 음악을 직접 지어내지 않고, 사전 검색(U-005)을 통해 확보한 실존 Spotify 트랙 후보군(`MappedTrack[]`)의 메타데이터 컨텍스트 범위 내에서만 최종 큐레이션 곡을 엄선합니다.
- **곡수 및 아티스트별 깊이 규칙**:
  - 최종 큐레이션 결과는 2~3시간 분량(약 30~50곡)의 플레이리스트 생성을 허용합니다.
  - 플레이리스트 내에 동일 아티스트가 포함될 경우, 해당 아티스트당 최소 3곡 확보를 목표로 수집 및 선별합니다. 검색 결과가 부족하거나 부적합한 곡만 있을 경우 1~2곡만 포함할 수 있으며, 이 경우 부족 사유를 `artistDepthNotes` 메타데이터에 기록합니다.
  - 분위기에 어울리는 이유를 설명하는 큐레이션 사유를 각 트랙/그룹별 코멘트 및 플레이리스트 설명(`playlistDescription`)에 반영합니다.

## 3. 라인업 제한형 페스티벌 큐레이션 규칙

- **모드 전환**: 사용자 프롬프트에 페스티벌, 라인업, 예습 등의 명시적 키워드가 포함될 경우 시스템은 `lineup-constrained` 모드로 전환합니다.
- **하드 제약 allowedArtists**: 프롬프트의 라인업 블록에서 추출된 아티스트 목록은 단순 선호가 아닌 최상위 하드 제약이 되며, 최종 결과의 모든 트랙은 `allowedArtists` 또는 그 `allowedArtistAliases`와 매칭되어야 합니다. 매칭되지 않는 아티스트의 트랙은 검증/수리 단계에서 전면 제외됩니다.
- **취향 반영의 한계**: 사용자가 명시한 취향 키워드(예: 어두운 밴드 사운드)는 라인업 외부 아티스트 추가의 근거가 될 수 없으며, 라인업 내 아티스트 곡들의 정렬 및 점수화 기준으로만 활용됩니다.

## 4. 파싱 에러 발생 시의 자동 복구 및 폴백 규칙

- **1차 자동 재수행**: LLM의 응답 내용이 정의된 JSON 규격을 충족하지 못해 파싱 오류(`JSON.parse` 예외 등)가 발생하는 경우, 백엔드는 즉시 파싱 실패 원인을 템플릿에 추가하여 1회에 한해 LLM에 수정 재요청을 보냅니다.
- **최종 폴백(Fallback) 수립**: 2차 재수행마저 실패하거나, LLM 호출 중 물리적인 네트워크 타임아웃/장애가 발생하는 경우에는 프로세스를 차단하지 않고 안전하게 준비된 디폴트 플레이리스트 데이터를 반환합니다.
  - **디폴트 폴백 결과 구조**:
    - 플레이리스트 제목: `"AI Curated Playlist"`
    - 플레이리스트 설명: `"AI 큐레이션 처리에 일시적인 오류가 발생하여, 사용자의 최근 재생 곡 목록을 기반으로 임시 구성된 플레이리스트입니다."`
    - 추천 트랙 목록: 사용자가 전달한 최근 재생 트랙 목록(`recentTracks`)의 텍스트(제목, 아티스트명) 중 최대 30건을 그대로 추천 곡으로 이식합니다.

## 5. 생성 후 검증 및 자동 수리 규칙 (validate-repair-final)

- **결정적 규칙 우선 검증**: 플레이리스트 저장 전, 다음 세 수준의 검증을 코드로 자동 실행합니다.
  - **하드 제약 검증**: `allowedArtists` 위반 여부 (라인업 모드 전용), 중복 트랙 검출, Spotify track URI 유효성(prefix `spotify:track:`) 검사.
  - **커버리지 검증**: 아티스트별 최소 3곡 목표 충족 여부 검사.
  - **품질 검증**: 사용자 취향 반영 및 에너지 전개 흐름 검증.
- **자동 수리(Repair)**: 하드 제약 위반 트랙이 검출되면 해당 트랙을 제거하고, 수집된 후보군 중 검증을 통과한 백업 트랙들로 대체하여 플레이리스트를 재구성합니다.
- **메타데이터 기록**: 제외된 트랙 사유, 아티스트별 곡수 부족 사유 등을 `validation` 결과 메타데이터에 기록하여 API 응답에 포함합니다.
