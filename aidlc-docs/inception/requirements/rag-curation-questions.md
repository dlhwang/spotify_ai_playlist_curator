## Question 1: 스포티파이 추천 시드(Seed) 추출 전략

스포티파이 Recommendations API(`GET /v1/recommendations`)는
**최대 5개의 시드** 파라미터(`seed_artists`, `seed_genres`, `seed_tracks`)
조합만 허용합니다. 사용자의 자연어 감정 프롬프트와 최근 재생 이력(최대
20곡)으로부터 이 5개의 시드를 어떻게 추출하여 API에 전달할까요?

* **A)** 최근 재생 곡들 중에서 중복 빈도가 가장 높은 장르/아티스트를
  5개 선정하는 단순 정적 규칙 기반 (최근 취향 극대화)
* **B)** 유저의 자연어 프롬프트를 1차로 초경량 LLM에 넘겨, 프롬프트
  분위기에 어울리는 대표 스포티파이 장르/아티스트 5개를 추출하여
  시드로 사용 (프롬프트 의도 부합 극대화)
* **C)** 고정된 장르(예: pop, chill) 2개와 유저 최근 곡 중 3개를
  시드 트랙으로 전송하는 고정형 하이브리드 조합 (구현 복잡도 최소화)
* **X)** Other (하단에 상세 기술)

[Answer]:B

## Question 2: LLM 컨텍스트(Context) 정보 및 오디오 피처(Audio Features) 활용 범위

스포티파이 추천 API가 반환한 후보군(예: 30~50곡) 중 최종 플레이리스트에
담을 10~15곡을 선별하기 위해 LLM에 텍스트 지식을 주입할 때, 어느 수준의
메타데이터를 포함할까요?

* **A) 텍스트 최소화**: 곡 제목 + 아티스트명만 전달 (토큰 비용 절약 및
  응답 시간 단축)
* **B) 오디오 특성 포함**: 곡명 + 아티스트명 외에 스포티파이가 제공하는
  오디오 피처 값(`valence` (밝기), `energy` (에너지), `tempo` (비피엠),
  `danceability` (댄스성))을 같이 전달하여 LLM이 곡의 감성적 조화를
  정교하게 필터링하도록 유도
* **X)** Other (하단에 상세 기술)

[Answer]:B

## Question 3: 취향(Recent History) vs 분위기(User Prompt) 가중치 정책

추천 리스트를 가공할 때 "사용자의 평소 취향(최근 들은 곡)"과
"사용자가 지금 새로 입력한 분위기(프롬프트)" 중 어느 쪽에 더 큰
가중치를 부여할까요?

* **A) 분위기(프롬프트) 우선**: 최근 재생 기록은 음악 데이터 검색을
  위한 시드로만 참고하고, 최종 선별 시에는 입력된 프롬프트와 가장
  일치하는 무드의 곡들 위주로 필터링
* **B) 개인 취향 우선**: 사용자의 최근 재생 곡 및 선호 아티스트의
  유사 곡들이 최소 60~70% 이상을 차지하도록 설계하여, 분위기가 다소
  어긋나더라도 평소 취향에 맞는 곡 중심 구성
* **C) 사용자 제어식 (동적)**: 프론트엔드 UI에 "내 취향 반영 비율"
  슬라이더(0% ~ 100%)를 배치하여, 백엔드 추천 프롬프트 및 API 호출
  인자에 동적으로 가중치 변수를 넘겨 처리
* **X)** Other (하단에 상세 기술)

[Answer]: A

## Question 4: Recommendations API 결과 전무/실패 시의 폴백(Fallback) 정책

스포티파이 추천 API가 특정 시드 조합으로 인해 검색 결과를 하나도
반환하지 않거나, 통신 오류/제한으로 실패했을 때의 폴백 시나리오는
어떻게 구성할까요?

* **A) 단순 이력 추천**: 최근 재생한 곡 목록을 그대로 추천 결과로
  반환 (현재 폴백 방식 유지)
* **B) 테마별 정적 추천**: 분위기별(비오는 날, 새벽 감성, 드라이브,
  신나는 운동 등) 5가지 대표 장르의 정적 플레이리스트 세트를 백엔드에
  미리 마련해 두고, 해당 장르로 Spotify Search를 돌려 추천
* **X)** Other (하단에 상세 기술)

[Answer]: A
